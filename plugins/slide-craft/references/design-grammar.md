# 슬라이드 디자인 문법 v1.0.0 (slide-craft design grammar)

보고·제안 슬라이드 한 장을 **읽히게** 만드는 문법의 정본(SSOT). 제작 스킬(`slide-craft`)과 진단 스킬(`slide-clinic`), 그리고 진단 에이전트(`design-diagnostician`)가 모두 이 파일 하나를 기준으로 판정한다.

문법은 **3축 + 1 상수**로 구성한다.

| 축 | ID | 한 줄 정의 | 확인 질문 |
|---|---|---|---|
| 콘텐츠 강약 | `E` (Emphasis) | 한 장에 주연은 하나다 | 이 장에서 제일 먼저 읽혀야 할 한 문장이 제일 크게 보이는가? |
| 콘텐츠 그룹화 | `G` (Grouping) | 같은 급의 정보는 한 그릇에 담는다 | 눈에 잡히는 시각 덩어리가 몇 개인가? 그 수가 정보의 층 수와 같은가? |
| 글 가독성 | `R` (Readability) | 레이아웃이 문장 길이를 따라간다 | 불릿이 한 행에 끝나는가? 끝나지 않으면 왜 이 레이아웃인가? |
| 에셋 상수 | `A` (Asset) | 이미지는 원본 그대로, 레이아웃이 비켜간다 | 이미지를 손대야 맞아떨어지는 레이아웃인가? |

심각도는 3단계다.

- **S1 (치명)** — 한 건만 있어도 장의 목적이 무너진다. 무조건 고친다.
- **S2 (높음)** — 한두 건은 넘어가지만 누적되면 장이 읽히지 않는다. 밀도로 판정한다.
- **S3 (낮음)** — 단독으로는 무해하다. 다른 증상과 겹칠 때만 가중한다.

## 0. 수치 스펙 레이어

레퍼런스 3종을 1280×720 기준으로 계측해 확정한 값이다. 컴포넌트(`components/`)의 CSS가 이 표를 그대로 구현한다. **수치를 바꾸려면 이 표부터 바꾸고 컴포넌트를 따라 고친다** — 컴포넌트에서 임의로 이탈하지 않는다.

### 0-1. 캔버스·그리드

| 항목 | 값 |
|---|---|
| 캔버스 | `1280 × 720` (16:9) |
| 배경 | `#F6F7F9` — 순백 카드와 대비를 만들기 위한 뉴트럴 그레이 |
| 콘텐츠 박스 | `x = 46 … 1234` (좌우 여백 46px 대칭 · 폭 **1188px**) |
| 푸터 | 좌 27px / 우 29px (본문보다 19px 바깥 — 의도적 이탈) · 텍스트 상단 `y = 682` |
| 카드 라운드 | `16px` (단일 카드 18px 허용) |
| 카드 그림자 | `0 3px 14px rgba(16,24,40,.055)` — 거의 안 보일 만큼 옅게 |
| 컬럼 분할 | 정확한 n등분 (`flex:1 1 0`). 5분할 237.6px · 3분할 396px |
| 컬럼 구분선 | `1px` · `#EFEFF1`(흰 카드) / `#F0F0F2`(통계 컨테이너) · 상하 인셋 비대칭(상 35~38 / 하 33~60) |

### 0-2. 타이포 스케일

| 역할 | 크기 | 두께 | 색 | 행간 |
|---|---|---|---|---|
| 아이브로 | **26.3px** | 700 | `#2B5FE0` | 1 |
| 헤드라인 | **44px** | 800 | `#000000` | **56px** (1.27) · ls −0.01em |
| 키워드 하이라이트 | 헤드라인과 동일 | 800 | `#FFFFFF` on `#2B64F1` | 박스 높이 55px · padding `2px 5px` |
| 메타 라벨 | 22.4px | 700 | `#1A1A1A` | 행 피치 **44px** |
| 메타 본문 | 22.4px | 400 | `#8A8B8F` | 〃 |
| 카드/통계/다크 제목 | **25px** | 700~800 | `#111113`~`#1A1A1A` | 1 |
| 통계 수치 | 29px | 800 | `#2B5FE0` | 1 |
| 통계 라벨 | 22.5px | 500 | `#3A3A3C` | **25px** (1.11 — 매우 타이트) |
| 통계 보조 | 21.3px | 400 | `#B3B3B6` | 1 |
| 아이콘 카드 설명 | 19.6px | 400 | `#AEAEB2` | 22.5px |
| 다크 불릿 | 19.6px | 400 | `#E6E6E8` | 행 피치 29px |
| 결론 화살표 행 | 19.6px | 700 | `#2B5FE0` | 1 |
| 카드 태그 | 19px | 400 | `#A0A0A4` | 1 |
| 카드 불릿 | 17px | 400 | `#B4B4B8` | 행 피치 23.5px |
| 푸터 | 17px | 500 | `#A1A2A6` | 1 |

**스케일 비율 리듬 — 헤드라인 : 준제목 : 본문 ≈ 2.6 : 1.4 : 1.0.**
헤드라인(44)만 압도적으로 크고 나머지는 17~26px의 좁은 대역에 몰려 있다. 이것이 "강약은 한 곳에서만 준다"의 수치적 실체다. **중간 크기(30~40px)를 만들면 주연이 둘이 된다** — 이 대역은 비워 둔다.

### 0-3. 컬러 팔레트

```
--bg        #F6F7F9   캔버스
surface     #FFFFFF   카드
--ink       #000000   헤드라인
ink-2       #1A1A1A / #111113   카드 제목 · 다크 컨테이너 배경
--accent    #2B5FE0   아이브로 · 통계 수치 · 결론행
--hl        #2B64F1   키워드 하이라이트 박스 배경
body-gray   #8A8B8F   메타 본문
mute-gray   #AEAEB2 / #B4B4B8 / #B3B3B6   설명 · 불릿 · 보조
tag-gray    #A0A0A4   카테고리 태그
divider     #EFEFF1 / #F0F0F2
footer      #A1A2A6
```

**유채색은 파랑 1종만 쓴다.** 나머지는 전부 무채 6단계 그레이. 색으로 강약을 주는 자리는 (1) 아이브로 (2) 키워드 하이라이트 (3) 통계 수치 (4) 결론행 — 이 넷뿐이다. 카테고리 태그를 색으로 구분하기 시작하면 색이 두 번째 강약 축이 되어 헤드라인의 우위가 깨진다(→ `E-4`).
예외: 아이콘 원형의 채색은 장식이지 정보 위계가 아니므로 다색 허용.

### 0-4. 수직 리듬 앵커 (3장 공통)

| 앵커 | y (잉크 상단) |
|---|---|
| 아이브로 | **46** |
| 헤드라인 1행 | **89~93** (아이브로 대비 +45) |
| 본문 블록 시작 | 177(헤드라인 1행) / 226(2행) / 329(2행+메타 2행) |
| 콘텐츠 하단 | 645~659 |
| 푸터 | **686** |

본문 블록 시작 y는 **헤드라인 행수와 메타 행수의 함수**다. 임의값을 쓰지 말고 위 셋 중에서 고른다.

### 0-5. 행 길이 상한 (가독성 축의 수치 근거)

한글 1자의 실효 폭 ≈ **폰트 크기 × 0.96**, 공백·라틴·숫자 ≈ **× 0.45** (Pretendard, ls −0.02em 기준).

```
행폭(px) ≈ (한글자수 × 0.96 + 공백·라틴자수 × 0.45) × 폰트크기
```

| 자리 | 폭 | 상한 (한글 기준) |
|---|---|---|
| 헤드라인 | 1188px @44px | **1행 26자 · 최대 2행** |
| 메타 본문 | 1054px @22.4px | 1행 46자 · **1행 고정** |
| 다크 컨테이너 불릿 | 544px @19.6px | **1행 28자 · 줄바꿈 금지** |
| 넓은 카드 불릿 | 351px @17px | **1행 20~23자 · 줄바꿈 금지** |
| 넓은 카드 제목 | 367px @25px | 1행 11~15자 |
| 결론행 | 367px @19.6px | 1행 12~20자 |
| 아이콘 카드 설명 | 238px @19.6px | 1행 12~13자 · **3행 고정** |

이 수치는 **사전 견적용 추정치**다. 확정은 언제나 렌더 후 실측으로 한다(`scripts/measure.js`).

### 0-6. 개수 상한

| 항목 | 상한 | 근거 |
|---|---|---|
| 최상위 시각 덩어리(컨테이너) | **2개** (권장 1~2) | 3개 이상이면 시선 진입점이 분산(→ `G-1`) |
| 한 컨테이너 안의 동급 분할 | **5개** (권장 3~5) | 6분할부터 컬럼 폭이 행 길이 상한을 깬다 |
| 독립 카드 그리드 | **4개** (2×2) | 4개 초과 시 카드 폭이 좁아져 `R-1` 발생 |
| 키워드 하이라이트 | **1장에 1개소** | 2개소 = 주연 2명 |
| 카드당 불릿 | **정확히 3개** (+ 결론 1행) | 3장 레퍼런스 전 카드 공통 |
| 메타 행 | **2행** | 3행부터 헤드라인 하단 여백을 잠식 |

## 1. 축 E — 콘텐츠 강약 (주연 승격 · 조연 강등)

### 원칙

**한 장에는 주연이 하나다.** 그 장에서 청중이 가져가야 할 단 하나의 메시지를 헤드라인으로 승격해 압도적으로 크게 두고, 그 안에서도 핵심 키워드에만 하이라이트를 건다. 나머지 정보는 전부 조연이며, 조연끼리는 서로 크기 경쟁을 하지 않는다. 시선은 위에서 아래로 **한 줄기**로 흐른다.

### 확인 질문

> 이 장에서 제일 먼저 읽혀야 할 한 문장이, 실제로 제일 크게 보이는가?
> 눈이 처음 떨어지는 지점이 하나인가, 둘인가?

### 증상 (before)

| ID | 증상 | 심각도 |
|---|---|---|
| `E-1` | **진입점 이중화** — 좌우 2단으로 나뉘어 좌측 제목 블록과 우측 목록 블록이 시각 무게가 대등하다. 눈이 어디서 시작할지 스스로 정해야 한다. | S1 |
| `E-2` | **헤드라인 미승격** — 핵심 문장이 본문과 비슷한 크기로 문단 안에 섞여 있다. 배율이 1.5배 이하면 "크다"로 읽히지 않는다. | S1 |
| `E-3` | **조연 과체중** — 배경·출처·범위 같은 보조 정보가 박스·카드를 얻어 본문 면적의 3분의 1 이상을 차지한다. | S2 |
| `E-4` | **강약 축 중복** — 크기 외에 색·번호·배지가 각각 독립적으로 강약을 주장한다(예: 항목마다 다른 색 번호). 축이 셋이면 강약은 사라진다. | S2 |
| `E-5` | **중간 크기 정체** — 30~40px 대역의 준헤드라인이 존재해 헤드라인과 본문 사이 위계가 뭉갠다. | S3 |

### 처방 (fix recipe)

1. 원고에서 **이 장의 한 문장**을 고른다. 없으면 만들지 말고 원고 작성자에게 되돌린다.
2. 그 문장을 `44px/800`, 최대 2행, 행간 56px로 캔버스 상단에 건다 → `01-eyebrow-headline.html`
3. 그 문장 안에서 **어절 단위 키워드 1개소**에만 `#2B64F1` 하이라이트를 건다. 문장 전체나 두 곳에 걸지 않는다.
4. 배경·범위·출처는 카드를 회수하고 **1행짜리 메타 행 2개**로 강등한다 → `02-meta-row.html`
5. 항목 목록은 캔버스 하단 한 덩어리(아이콘 카드 열)로 내려 **좌→우 한 줄**로 편다 → `03-icon-card-row.html`
6. 번호·색 배지를 제거한다. 순서가 정말 의미 있으면 좌→우 배치 자체가 순서다.

### 수치 규칙

- 헤드라인 / 최대 본문 크기 비 ≥ **1.5** — 아이브로(26.3px)와 위첨자는 제외한다. 아이브로는 헤드라인 위에 붙는 라벨이라 주연 자리를 다투지 않는다. 레퍼런스 3종 실측 **1.52 ~ 1.76** (통계 수치 29px이 있는 장이 하한)
- 30~40px 대역 **사용 금지** — 비율보다 이쪽이 더 날카로운 판정 기준이다
- 하이라이트 1개소 · 유채색 사용처 4곳 이내(0-3 참조)
- 메타 행 ≤ 2 · 각 1행 · 라벨 폭 고정 100px

### 컴포넌트 매핑

`01-eyebrow-headline` · `02-meta-row` · `03-icon-card-row`

## 2. 축 G — 콘텐츠 그룹화 (한 그릇에 담기)

### 원칙

**카드 개수 = 인지 부하.** 정보가 여섯 조각으로 나뉘어 있다는 사실 자체가 청중에게 "여섯 번 읽어라"라고 말한다. 같은 층위의 정보는 카드 경계를 지우고 **하나의 컨테이너 안에서 구분선으로만** 나눈다. 층이 다른 정보끼리는 컨테이너를 붙여 이음매 없는 한 덩어리로 만든다.

### 확인 질문

> 눈에 잡히는 시각 덩어리가 몇 개인가?
> 그 개수가 실제 정보의 층 수와 같은가, 아니면 제작 편의로 늘어난 것인가?

### 증상 (before)

| ID | 증상 | 심각도 |
|---|---|---|
| `G-1` | **카드 파편화** — 동급 항목이 각각 독립 카드(배경·라운드·여백을 다 가진)로 떠 있다. 카드 사이 간격이 카드 안 여백과 비슷해 어디까지가 한 묶음인지 안 보인다. | S1 |
| `G-2` | **덩어리 과다** — 최상위 시각 덩어리가 3개를 넘는다(리드문 블록 + 통계 3장 + 이미지 + 다크박스 = 6). | S1 |
| `G-3` | **떠도는 리드문** — 헤드라인이어야 할 문장이 카드도 헤드라인도 아닌 채 여백에 얹혀 어느 그룹에도 속하지 않는다. | S2 |
| `G-4` | **이미지 고립** — 이미지가 자기 테두리·플레이스홀더 프레임을 갖고 별도 카드로 서서, 설명 텍스트와 짝이라는 사실이 시각적으로 드러나지 않는다. | S2 |
| `G-5` | **여백 리듬 불일치** — 카드 간 gap이 자리마다 달라(12/16/24px 혼용) 묶음 경계가 흔들린다. | S3 |

### 처방 (fix recipe)

1. 정보를 **층**으로 먼저 분류한다: 요약 수치층 / 단서·제외 조건층 / 근거 이미지층.
2. 같은 층은 **하나의 흰 컨테이너**에 넣고 카드 경계를 지운 뒤 `1px #F0F0F2` 구분선으로만 나눈다. 분할은 정확한 n등분 → `04-stat-container.html`
3. 다른 층은 **같은 컨테이너에 세로로 이어 붙인다**. 부모에 `border-radius:16px; overflow:hidden`을 주면 자식 블록의 경계가 사라지고 이음매 없는 한 덩어리가 된다 → `05-dark-callout-image.html`
4. 이미지는 그 층의 컨테이너 **내부 우측에 flush**로 박는다. 별도 프레임·캡션 박스를 주지 않는다. 다크 배경과 만나는 쪽만 90px 그라디언트로 녹인다.
5. 떠도는 리드문은 헤드라인으로 흡수하거나 삭제한다. 세 번째 자리는 없다.
6. 남은 최상위 덩어리를 센다. **2개 초과면 다시 1로 돌아간다.**

### 수치 규칙

- 최상위 덩어리 ≤ **2**
- 컨테이너 내 동급 분할 3~5 · 정확한 n등분
- 구분선 `1px` · `#EFEFF1`/`#F0F0F2` · 상하 인셋 비대칭 (상 35 / 하 33)
- 결합 컨테이너: `radius 16 + overflow:hidden`, 자식은 라운드 없음
- 이미지 슬롯 폭: 다크 결합 시 574px(전체 폭의 48%) · 카드 내부 190px

### 컴포넌트 매핑

## 3. 축 R — 글 가독성 (레이아웃이 문장을 따라간다)

### 원칙

**문장을 레이아웃에 욱여넣지 않는다. 레이아웃을 문장 길이에 맞춘다.**
불릿 한 개는 한 행에서 끝나야 한다. 두 행으로 넘어가면 폰트를 줄이거나 글자를 쳐내는 게 아니라 **레이아웃을 바꾼다** — 좁은 세로 카드 4개를 넓은 가로 카드 2×2로 바꾸면 텍스트 영역이 230px에서 367px로 늘어나 같은 문장이 한 행에 담긴다.

### 확인 질문

> 불릿이 한 행에 끝나는가?
> 마지막 행에 한두 글자만 남은 자리가 있는가?
> 이 문장이 두 행인 것은 의도인가, 카드가 좁아서인가?

### 증상 (before)

| ID | 증상 | 심각도 |
|---|---|---|
| `R-1` | **불릿 다행 줄바꿈** — 불릿마다 2~3행으로 접혀 말머리 기호가 텍스트 블록 사이에 파묻힌다. 항목 경계가 행 경계와 구분되지 않아 몇 개인지 세어야 한다. | S1 |
| `R-2` | **고아 어절** — 줄바꿈 후 마지막 행에 1~2글자만 남는다("…가구에 중 / 요"). 단어가 잘려 읽는 속도가 끊긴다. | S1 |
| `R-3` | **세로 카드 강요** — 항목 수를 열 수로 그대로 옮겨 카드가 세로로 좁고 길어졌다. 폭은 텍스트가 아니라 개수가 정했다. | S1 |
| `R-4` | **하단 공백 웅덩이** — 불릿 블록과 카드 하단 결론 사이에 목적 없는 빈 공간이 남아, 카드마다 그 크기가 다르다. | S2 |
| `R-5` | **항목 수 불균일** — 카드마다 불릿이 2~4개로 달라 카드 높이와 리듬이 어긋난다. | S2 |
| `R-6` | **폰트 축소 미봉** — 행에 맞추려고 특정 카드만 폰트를 1~2px 줄였다. 스케일이 깨지고 그 카드만 흐려 보인다. | S2 |

### 처방 (fix recipe)

1. 원고의 불릿을 **길이순으로 계측**한다. 최장 문장이 기준이다.
2. 최장 문장이 한 행에 들어가는 **텍스트 영역 폭**을 0-5의 식으로 역산한다.
3. 그 폭이 나오는 레이아웃을 고른다.
   - 필요 폭 ≤ 240px → 세로 컬럼(아이콘 카드 열) 가능
   - 240 < 필요 폭 ≤ 370px → **넓은 가로 카드 2×2** → `06-wide-card.html`
   - 필요 폭 > 370px → 카드를 버리고 전폭 컨테이너 불릿 → `05-dark-callout-image.html`
4. 카드 구조를 **태그 → 제목 → 불릿 3개 → 결론 1행**으로 통일한다. 불릿 개수를 카드마다 맞춘다.
5. 그래도 안 들어가면 **원고를 줄인다**. 폰트를 줄이지 않는다.
6. 이미지 슬롯은 텍스트 영역을 침범하지 않는 고정 폭(190px)으로 카드 우측에 붙인다.

### 수치 규칙

- 불릿 1행 고정. 실측 행 높이 = 폰트 크기 × 1.0~1.4 범위를 벗어나면 줄바꿈 발생으로 판정
- 넓은 카드: 586 × 227px · column-gap 16 · row-gap 15 · 텍스트 영역 367px(586 − 190 − 29)
- 카드 내부 리듬: 상 28 / 좌 29 → 태그 → 10 → 제목 → 14 → 불릿(gap 5, 피치 23.5) → 16 → 결론행
- 불릿 마커: `4×4` 정사각 `#C9C9CD` · 들여쓰기 16px (원형·문자 불릿 금지)
- 카드당 불릿 정확히 3개 · 결론 1행
- 폰트 크기는 0-2 표의 값만 사용. 카드별 미세 조정 금지

### 컴포넌트 매핑

`06-wide-card` · `03-icon-card-row` · `07-image-slot`

## 4. 상수 A — 에셋 이미지 중심, 원본 그대로

### 원칙

**사용자가 준 이미지는 자산이지 재료가 아니다.** 자르지 않고, 보정하지 않고, 다시 만들지 않는다. 이미지는 고정 블록이고 **레이아웃이 그 블록을 피해 짜인다**.

### 증상

| ID | 증상 | 심각도 |
|---|---|---|
| `A-1` | 이미지를 크롭·리터치·재생성해 슬롯에 맞췄다 | S1 |
| `A-2` | 이미지 위에 텍스트를 얹어 원본 화면을 가렸다 | S1 |
| `A-3` | 이미지가 슬롯 비율과 달라 늘어나거나 찌그러졌다 | S1 |
| `A-4` | 이미지에 캡션 박스·테두리 프레임을 둘러 별도 카드로 만들었다 (→ `G-4` 동반) | S2 |

### 처방

- 슬롯은 `object-fit: cover` + `object-position` 조정으로만 대응한다. 원본 파일은 건드리지 않는다.
- 원본 비율이 슬롯과 크게 어긋나면 **슬롯 치수를 바꾼다**(카드 이미지 폭 190 → 220 등). 그리고 그 변경을 텍스트 영역 폭에 반영해 `R` 축을 다시 검산한다.
- 이미지가 어두우면 텍스트를 이미지 밖으로 뺀다. 오버레이를 씌우지 않는다.
- 이미지가 아직 없으면 `07-image-slot.html`의 회색 플레이스홀더를 그대로 둔다. 임의 이미지로 채우지 않는다.

## 5. 판정 체크리스트 (진단용)

`slide-clinic`이 렌더 결과 1장에 대해 순서대로 돌린다. 각 항목은 **육안이 아니라 계측**으로 판정한다 — `scripts/measure.js`가 뽑는 필드를 괄호로 적었다.

```
[E] 강약
  E-1  시각 진입점이 1개인가                     (좌우 2단 대칭 배치 여부 · surfaces 좌표)
  E-2  헤드라인/최대본문 비 ≥ 1.5 인가           (headline.ratio · 아이브로 제외)
  E-3  보조 정보가 본문 면적의 1/3 이하인가       (surfaces 면적 합)
  E-4  유채색 사용처가 4곳 이하 · 하이라이트 1개소인가  (colors · highlightCount)
  E-5  30~40px 폰트가 존재하지 않는가            (typeScale)

[G] 그룹화
  G-1  동급 항목이 독립 카드로 분리돼 있지 않은가  (surfaceGroupDetail)
  G-2  시각 덩어리 그룹 ≤ 2 인가                 (surfaceGroups — 같은 클래스·같은 치수의
       균일 그리드는 1개 그룹으로 센다. 카드 4장짜리 2×2 그리드 = 1그룹)
  G-3  어느 그룹에도 속하지 않는 텍스트 블록이 없는가
  G-4  이미지가 자체 프레임 없이 컨테이너에 내장돼 있는가
  G-5  동일 층 gap이 단일 값인가

[R] 가독성
  R-1  자동 줄바꿈이 0건인가                     (autoWrapped — 선언 행수(<br>+1)보다
       렌더 행수가 많은 블록. 의도한 3행 설명은 위반이 아니다)
  R-2  마지막 행 글자 수 ≥ 3 인가                (줄바꿈이 있는 블록만)
  R-3  넘침이 0건인가                            (overflowing)
  R-4  카드 간 하단 여백 편차 ≤ 8px 인가
  R-5  카드별 불릿 개수가 동일한가                (bulletCountsEqual)
  R-6  폰트 크기 집합이 0-2 표의 부분집합인가      (offScale == [] · 위첨자 제외)

[A] 에셋
  A-1  이미지 파일이 원본 그대로인가 (해시·치수 대조)
  A-2  이미지 위에 텍스트 레이어가 없는가
  A-3  슬롯 비율 ≈ 원본 비율인가 (object-fit 외 왜곡 없음)
  A-4  이미지에 별도 프레임·캡션 박스가 없는가

[공통] 스펙 준수
  S-1  캔버스 1280×720 · 여백 46 · 푸터 y686
  S-2  색이 0-3 팔레트 안에 있는가
  S-3  본문 블록 시작 y가 {177, 226, 329} 중 하나인가
```

**판정 규칙** — S1이 하나라도 있으면 `FAIL`. S1이 없고 S2가 3건 이상이면 `FAIL`. 그 외 `PASS`.

**회귀 기준선** — `examples/` 4장(레퍼런스 3종 + 스모크 테스트)은 언제나 `PASS`여야 한다. 실측 기준값:

| 파일 | typeScale off | headline.ratio | surfaceGroups | autoWrapped | overflowing | bullets |
|---|---|---|---|---|---|---|
| `slide1-emphasis` | 0 | 1.76 | 1 | 0 | 0 | — |
| `slide2-grouping` | 0 | 1.52 | 1 | 0 | 0 | [3] |
| `slide3-readability` | 0 | 1.76 | 1 | 0 | 0 | [3,3,3,3] |
| `smoke-test` | 0 | 1.76 | 1 | 0 | 0 | — |

문법 수치를 고친 뒤 이 표가 깨지면, 규칙이 과한 것인지 예시가 낡은 것인지 판정하고 기록한다.

## 6. 성장 루프 — 새 사례를 문법으로 승격하는 절차

새 before/after 사례가 들어오면 다음 순서로 처리한다. **사례를 그대로 쌓지 않고 문법으로 증류한다.**

```
1. 인입   before/after 한 쌍을 확보하고, 무엇이 바뀌었는지 계측으로 기술한다
          (레이아웃 치수 · 폰트 · 개수 · 색 — 인상 서술 금지)
2. 귀속   변화를 기존 축 E/G/R/A 중 하나로 설명할 수 있는가?
          → 설명된다: 해당 축의 증상 표에 하위 패턴을 추가한다 (ID는 뒤에 이어 붙인다)
          → 설명 안 된다: 후보 풀에 넣고 보류한다. 축은 함부로 늘리지 않는다
3. 검증   같은 패턴이 서로 독립인 사례 2건 이상에서 재현되는가?
          1건짜리는 승격하지 않는다 (그 장의 사정일 수 있다)
4. 수치화 처방에 숫자를 붙일 수 있는가? 붙일 수 없으면 승격하지 않는다
          ("답답해 보인다"는 문법이 아니다 / "텍스트 영역 240px 미만"은 문법이다)
5. 승격   증상 표 + 처방 + 수치 규칙 + 컴포넌트 매핑 4종을 동시에 갱신한다
          필요하면 컴포넌트를 신설하고 examples/에 조립 예시를 넣는다
6. 회귀   기존 examples/ 3장을 다시 렌더해 새 규칙으로 판정한다
          기존 예시가 FAIL이 나면 규칙이 과하거나 예시가 낡은 것 — 어느 쪽인지 판정하고 기록한다
```

### 축 신설 기준

새 축은 다음을 **모두** 만족할 때만 만든다.

- 기존 3축 어디에도 귀속되지 않는 증상이 독립 사례 **3건 이상**에서 재현
- 확인 질문 한 문장으로 표현 가능
- 처방이 기존 축의 처방과 충돌하지 않음

축을 늘리는 것보다 하위 패턴을 늘리는 쪽이 항상 낫다. 축이 5개를 넘으면 진단이 체크리스트로 전락한다.

### 버전 규칙

| 변경 | 버전 | 예 |
|---|---|---|
| 문구 정리 · 수치 미세 보정 | patch (`1.0.1`) | 불릿 상한 23자 → 22자 |
| 하위 패턴 추가 · 컴포넌트 신설 | minor (`1.1.0`) | `R-7` 추가 |
| 축 신설 · 재편 · ID 체계 변경 | major (`2.0.0`) | 4번째 축 도입 |

패턴 ID는 **재사용하지 않는다**. 폐기된 패턴은 ID를 비워 두고 "보류/폐기"로 표시해 기존 리포트의 참조 무결성을 지킨다. 버전을 올리면 `plugin.json`·`marketplace.json`의 버전도 함께 올린다.
