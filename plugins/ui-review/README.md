# ui-review — 제품 UI에서 AI 티를 걷어내는 검수 하네스

AI로 UI/UX를 만들면 특유의 억양이 남는다: 레이아웃이 이미 말하는 것을 굳이 설명하는 안내문, 각주 같은 헤징 문장, 그리드에서 살짝 벗어난 간격, 근사값 브랜드 컬러, 스케일에서 한 단계 어긋난 헤딩, 그리고 "멋있어서" 넣은 모션. 이 플러그인은 그 억양을 항목·등급·file:line 단위로 적출하는 **검수 전용** 자매 스킬 2종이다. 화면을 생성하지 않는다 — 제작↔비평 페르소나 분리 원칙.

실서비스 운영 프로젝트(안드로이드 키오스크 앱)에서 이슈 67건 메타분석과 베이스라인 실측(합리화 대응표 27종)을 거쳐 승격된 자산이다.

## 스킬

| 스킬 | 페르소나 | 축 | 요약 |
|---|---|---|---|
| `design-review` | **Noa** | 정적 | 타이포 floor·8px 그리드·터치 티어(≥44dp)·대비(4.5:1)·브랜드 토큰 정확도 + **AI-tell 카피 검출**(잉여 안내문구 제거 원칙·내부용어/디버그 잔재 누출) — 검수 항목 A~M |
| `motion-review` | **Rei** (零 — 기본 답 "모션 0") | 시간 가변 | 절제 우선·빈도 티어(100+/day = 모션 금지)·4문 게이트·개선 위계(삭제>축소>이징>타이밍>재설계)·reduced-motion 의무·Compose 포팅 전표 101건 — 검수 항목 M-A~M-J |

두 스킬은 속성 축으로 범위를 가르고(정적=Noa, 모션=Rei), 같은 카드 문법을 공유해 다운스트림 스윕이 하나의 파서로 두 리포트를 처리할 수 있다.

## 설치

```
/plugin marketplace add sungwooHa/skills-marketplace
/plugin install ui-review@skills-marketplace
```

## 프로젝트 설정 (선택)

`ui-review.local.md.example` 을 프로젝트의 `.claude/ui-review.local.md` 로 복사해 프로젝트 값(디자인 스펙 경로, 모션 스펙 절, 금지 용어 목록, 고빈도 표면, 페어 화면)을 주입한다. 설정이 없으면 보편 floor(터치 44dp, 대비 4.5:1, 8px 그리드, 캡션 12sp, 모션 상한 300ms)만으로 degraded 동작하며 "스펙 부재"를 Critical로 보고한다.

## 사용

```
/design-review path/to/Screen.kt        # 정적 검수
/design-review all                      # UI 디렉터리 전체
/motion-review path/to/Screen.kt        # 모션 검수
/motion-review propose HomeScreen       # "모션 넣을까?" 4문 게이트 평가
```

인수 없이 호출하면 `git diff --name-only` 변경 파일을 검수한다.

## 철학

1. **삭제가 기본 수.** 잉여 카피도, 모션도, 확신이 없으면 지운다. "아무것도 살아남지 않음"은 유효한 검수 결과다.
2. **스펙이 유일한 기준.** 기억·취향으로 판정하지 않는다. 프로젝트 스펙이 없으면 보편 floor만 쓰고 그 부재 자체를 보고한다.
3. **모든 발견은 file:line.** "어딘가에 있다"는 보고는 없다.
4. **빈도가 스펙을 지배한다** (모션). 하루 100회 이상 노출되는 표면에 애니메이션은 판단 대상이 아니라 실격 대상이다.
5. **정보에는 동사가 따른다.** 집계·경고·카운트를 보여주면 다음 행동 경로가 같은 화면군 안에 있어야 한다.

## 기존 플러그인과의 경계

- **humanize-korean**: 산문(문서·글)의 AI 티 제거. ui-review는 **제품 UI 코드**(화면·컴포넌트)의 AI 티 검수 — 대상 아티팩트가 다르다. UI 문자열 카피 규칙(잉여 안내문구)은 ui-review 소관.
- **deck-harness / slide-craft**: 발표덱·보고 지면의 **생성** 파이프라인(자체 크리틱 포함). ui-review는 앱/웹 **제품 UI**의 검수 전용 — 생성하지 않으며, 대상도 산출물 지면이 아니라 소스 코드다.
- 프로젝트에 자체 프로젝트 전용 검수 스킬이 있으면 그쪽이 우선한다(스킬 description에 명시).
